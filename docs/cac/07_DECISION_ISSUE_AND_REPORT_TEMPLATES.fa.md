# قالب‌های استاندارد همکاری

## ثبت تصمیم معماری (`ADR`)
`ID | date | affected_scope | decision | alternatives | security/privacy impact | API/DB diff | owner APR required? | acceptance IDs | status`

## درخواست تغییر (`CR`)
`ID | requester | reason | baseline/spec hash | current behavior | desired behavior | impact: product/security/API/DB/UX | backward compatibility | test plan | approval owner/architect | Work action`

## گزارش Sprint از Work
`Sprint | repo+commit or ZIP sha256 | changed files | migrations & role context | executed tests with command/OS/DB | PASSED | FAILED | SKIPPED | blockers | security findings | preview/demo evidence | next steps`

## تابلوی مدیریت
`Priority P0/P1/P2 | epic | task | owner/agent | dependency | acceptance | planned/doing/blocked/review/done | evidence link | risk | next action`

## تعریف Done
یادداشت یا کد با «ساخته شده» به معنی پذیرش نیست؛ Done فقط بعد از schema/contract alignment، code review، test evidence روی محیط مربوط، security gate و signoff مناسب است. `SKIPPED` و `NOT_RUN` نباید به PASS تبدیل شوند.
