# مشخصات مبنای CAC V1 — محصول و تجربه کاربر

## مأموریت
CAC یک SaaS چندفروشگاهی برای صاحبان فروشگاه ووکامرس است: اتصال آسان به WooCommerce و ارائه دستیار AI با ویجت embeddable برای پاسخ‌گویی فقط از **اطلاعات عمومی و تأییدشده فروشگاه**. Backend هدف Django/DRF modular monolith، PostgreSQL/pgvector و RAG ترکیبی است. inference/embedding فقط از API ارائه‌دهنده **پس از تأیید قرارداد/حریم خصوصی/منطقه**؛ هیچ مدل خودمیزبان V1 الزامی نیست.

## V1 غیرقابل‌تغییر بدون CR/تصویب لازم
- داشبورد مدیریت فقط چهار بخش سطح اول: **نمای کلی، گفتگوها، اطلاعات دستیار، تنظیمات**. کاربر تازه‌کار درگیر token meter و حساب‌وکتاب مصرف نمی‌شود؛ اشتراک ماهانه ساده و نسخه‌های گران‌تر آینده بر مبنای قابلیت بیشتر.
- تا آماده‌شدن واقعی: `Preview خصوصی → تأیید مدیر → نصب → راستی‌آزمایی → Live`. **حداکثر یک دستیار عمومی فعال در هر Store**؛ مدل یک Store با چند Assistant برای آینده قابل‌گسترش است (`APR-034`).
- قبل از اولین Live وجود حداقل یک **راه تماس معتبر و attest شده توسط مدیر صاحب اختیار** ضروری است (`APR-033`). از دست‌رفتن قطعی آخرین راه تماس ⇒ Pause عمومی، Preview خصوصی باقی می‌ماند؛ timeout گذرای probe به‌تنهایی Pause نمی‌کند (`APR-035`).
- Widget با کلیک باز می‌شود؛ iframe روی مبدأ سرویس مجزا و پیام‌های `postMessage` با `origin/source/nonce/epoch` کنترل شوند؛ نشست visitor مجزا برای هر visit، بدون نمایش تاریخچه visitهای قبلی.
- V1 بدون سفارش‌گیری، خواندن order/customer/payment خصوصی ووکامرس، عملیات admin از سوی AI، اتصال human-agent یا SLA چت. تماس عمومی جایگزین امن هنگام توقف دستیار است.
- کاتالوگ فقط product/variant public؛ plugin Woo push signed + reconciliation/epoch/idempotency؛ قیمت دقیق صرفاً از داده معتبر حداکثر ۳۰ دقیقه، موجودی حداکثر ۱۰ دقیقه، heartbeat بدون مشاهده واقعی تازگی را تمدید نکند.
- دانش FAQ/policies از URL/file با محدودیت SSRF/quarantine و بازبینی انسانی منتشر شود؛ منابع حساس با تأیید دو reviewer مستقل. گفتگوهای بازدیدکنندگان به‌تنهایی منبع fact یا سند انتشار نیستند.
- نگهداری متن خام گفتگو: ۳۰ روز از آخرین پیام واقعی؛ API حتی پیش از پاکسازی فیزیکی باید پس از انقضا دسترسی را رد کند. retention نسخه‌های backup/vendor/مشتقات نیازمند بررسی مستقل است.

## معیار تجربه مدیر
مدیر بدون دانش فنی باید قدم‌های onboarding، اتصال افزونه، افزودن دانش، Preview و فعال‌سازی را بفهمد و بداند در هر blocker چه اقدامی لازم است. جزئیات SQL/provider/token/raw errors در UI عمومی ممنوع است.
