These are experimental dependencies, not approved technology contracts.

Three real isolated PostgreSQL instances A/B/C have distinct measured system identifiers. C contains legacy `anchor` generation/readiness cache and public `h_w` projection. R owns full state, operation tickets, idempotency/tombstones and ordered full-state journal. W never owns R signing keys, coordinator credentials or authoritative operation tickets. State and next journal entry are written in one etcd compare/transaction revision. Reads validate the whole contiguous digest chain and final state at a pinned MVCC revision; W's complete public replay is validated against actual current R history, not its own scalar epoch.

An independently current private controller/service profile outside A/B/C/W pins namespace, current verifier catalog, W SID and permitted actors. The controller commits NOLOGIN, drains old application sessions, checks its own canonical catalog measurement, effective private ACL/FORCE RLS and agreement with the live measurement before LOGIN. Legacy C-only/private/pre-R routines lose runtime/issuer grants. Every supported live protected SQL path, issuance, challenge and RLS read/write calls the current online R guard. Fresh nonce and current online verification bind root/policy/signer, node/incarnation/catalog, actual PG SID/PID/fullxid/login, operation ticket and exact intent. Experimental HMAC is not independent key custody or an approved protocol.

The owned coordinator is trusted to observe the exact PG transaction and positive COMMIT/ABORT ACK. Durable Root OPEN ACK precedes FIRST_USE. REVOKE blocks ungranted first use; an earlier grant may finish while all OPEN/UNKNOWN block successor. Root CLOSE requires exact owned transaction and known outcome; changed transaction, failed statement ambiguity or lost observer leave hold. No timeout/session exit/manual hard fence clears an orphan. Raw coordinator credentials can assert outcomes: this prototype is not a proof against a malicious trusted observer.

R minority recovery uses remove old identity, archive old directory, add fresh nonvoting learner, observe current full application journal with exact revision/member/cluster identity, then explicit promotion. Original r1/r2/r3 identities/current directories remain. Literal old Raft snapshot/WAL import, rewound original-voter boot and physical same-identity clone are not performed or supported. Application journal equality is not a claim of byte-identical internal Raft WAL.
