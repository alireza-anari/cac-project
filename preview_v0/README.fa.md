# CAC Preview V0 — اولین نسخه قابل‌اجرای محلی

یک فروشگاه آزمایشی بسازید، محصول اضافه کنید، دستیار را تغییر دهید و واقعاً با آن گفتگو کنید. اطلاعات در SQLite همین دستگاه می‌ماند. **هوش مصنوعی واقعی وصل نیست؛ پاسخ‌ها قوانین‌محور Demo هستند.**

فقط برای داده ساختگی و تجربه شخصی روی `127.0.0.1`. این نسخه SaaS عمومی، Live یا Production نیست. نصب Python و دریافت بسته‌های Python اینترنت می‌خواهد؛ برنامه هنگام اجرا اتصال بیرونی ندارد. Docker، PostgreSQL، Redis، Node و حساب ابری لازم نیست.

## ۱. پیش‌نیاز و استخراج

Python **3.12** نصب باشد. ZIP را در یک پوشه تازه استخراج کنید؛ داخل پوشه `preview_v0` ترمینال را باز کنید. کلید، رمز، دیتابیس و محیط آماده در ZIP وجود ندارد؛ روی دستگاه شما ساخته می‌شوند. نام کاربری محلی `demo` است، ولی رمز آن برای هر راه‌اندازی تازه تصادفی است.

### Windows — PowerShell

بدون فعال‌کردن محیط یا تغییر ExecutionPolicy:

```powershell
cd preview_v0
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py setup_demo
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

### macOS / Linux

```bash
cd preview_v0
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python manage.py migrate
.venv/bin/python manage.py setup_demo
.venv/bin/python manage.py runserver 127.0.0.1:8000
```

در مرورگر همین دستگاه باز کنید: **http://127.0.0.1:8000/**. نام کاربری `demo` و رمز تصادفی چاپ‌شده در خروجی `setup_demo` را وارد کنید. آن رمز را در گزارش، Git، ZIP یا تصویر منتشر نکنید. نصب یا اجرای مرورگر ابری با localhost دستگاه شما یکی نیست.

برای توقف، `Ctrl+C`. اجرای دوباره همان دستور runserver، داده قبلی را حفظ می‌کند. از `0.0.0.0`، تونل، reverse proxy و میزبانی عمومی استفاده نکنید؛ فرمان این برنامه bind غیر از `127.0.0.1:PORT` را رد می‌کند.

## ۲. تجربه کامل در حدود چند دقیقه

1. وارد شوید و «فروشگاه تازه» را بزنید؛ نام و توضیح ساختگی را ذخیره کنید.
2. در «نمای کلی»، دو محصول یا خدمت بسازید؛ مثلاً «قهوه عربیکا» با قیمت `125000` تومان و «مشاوره خرید» بدون قیمت. وضعیت در دسترس بودن را هم تغییر دهید.
3. یکی را ویرایش و یکی را با تأیید حذف کنید؛ یک مورد دیگر اضافه کنید تا فهرستتان حداقل دو مورد داشته باشد.
4. در «اطلاعات دستیار»، نام، خوشامد و سبک صمیمی/رسمی/کوتاه را ذخیره کنید؛ «بازکردن گفتگوی خصوصی» را بزنید.
5. بپرسید «سلام»، «چه محصولاتی دارید؟»، «قیمت قهوه عربیکا چقدر است؟»، «قهوه عربیکا موجود است؟». نام دقیق محصول بهترین نتیجه را می‌دهد.
6. قیمت را در نمای کلی به `99000` تغییر دهید و دوباره در گفتگو بپرسید؛ پاسخ جدید باید قیمت تازه داشته باشد. تاریخچه قدیمی عمداً بازنویسی نمی‌شود.
7. سؤال ناشناخته مثل «هوای فردا چگونه است؟» بپرسید؛ پاسخ باید نبود اطلاعات را بگوید، نه اطلاعات ساختگی. هر پاسخ برچسب Demo دارد.
8. صفحه را دوباره باز کنید؛ سرور را متوقف و دوباره اجرا کنید. فروشگاه، محصولات، تنظیمات دستیار و گفتگوها باید باقی باشند. چهار بخش اصلی و نبود هرگونه انتشار عمومی را ببینید.

**بازخورد مالک محصول:** بعد از این تجربه فقط بگویید: کدام بخش گیج‌کننده بود؟ ظاهر و مسیر با تصور شما چقدر فاصله دارد؟ سه تغییر مهم بعدی چیست؟ توسعه قابلیت تازه تا دریافت بازخورد متوقف می‌ماند.

## ۳. قواعد دقیق Demo

- «سلام» پیام خوشامد ذخیره‌شده را برمی‌گرداند؛ پیام نخست صفحه نیز همین خوشامد است.
- سؤال فهرست، حداکثر ۲۰ نام از کاتالوگ محلی را نمایش می‌دهد.
- نام کامل یا واژه حداقل سه‌حرفی از نام محصول/خدمت برای جست‌وجوی ساده استفاده می‌شود. چند نتیجه → درخواست نام دقیق؛ بدون نتیجه → اعلام نبود اطلاعات.
- پاسخِ مورد پیدا‌شده فقط نام، قیمت ثبت‌شده، وضعیت و توضیح ذخیره‌شده را دارد. نبود قیمت صریح است؛ سبک کوتاه توضیح را حذف می‌کند. این استدلال زبانی/درک معنایی AI نیست.
- هر پاسخ جدید داده ذخیره‌شده فعلی را می‌خواند. پاسخ قبلی یک رکورد تاریخی است؛ اصلاح محصول آن را بازنویسی نمی‌کند.
- تمام گفتگوها خصوصی و زیر ورود مالک هستند. customer-view فقط ظاهر گفتگوی خصوصی است؛ نشست بازدیدکننده عمومی یا لینک اشتراک‌گذاری ندارد.

## ۴. قابلیت‌ها و محدودیت‌ها

| وضعیت | موارد |
|---|---|
| WORKING_LOCAL | ورود/خروج استاندارد Django، فروشگاه و محصول/خدمت CRUD، یک دستیار خصوصی در هر فروشگاه، تنظیم نام/خوشامد/سبک، گفتگو و تاریخچه، SQLite و ماندگاری |
| DEMO_RULE_BASED | فهرست، تطبیق ساده نام، قیمت/موجودی/توضیح ثبت‌شده و fallback ناشناخته؛ بدون LLM |
| NOT_IMPLEMENTED | WooCommerce، AI واقعی، ثبت‌نام عمومی، MFA/IdP، تماس/دامنه معتبر، اشتراک/پرداخت، ویجت، قابلیت حذف تاریخچه از UI و retention خودکار ۳۰روزه |
| PRODUCTION_BLOCKED | انتشار عمومی/Live، داده واقعی، امنیت چندمستاجری عملیاتی، PostgreSQL/RLS، بازیابی توزیع‌شده، تمام گیت‌های انتشار |

این Preview فقط یک دستیار **خصوصی** برای هر فروشگاه می‌سازد. هیچ حالت یا route عمومی Live ندارد. APR-034 درباره حداکثر یک Live عمومی V1 تغییر نکرده، ولی امنیت Live در این نسخه اثبات نمی‌شود. ثبت محصول عمومی Woo یا محتوای تأییدشده Production در این پروژه محلی پیاده نشده است؛ تمام داده‌ها صرفاً ساخته خود کاربر آزمایشی‌اند.

### ایمنی و داده محلی

- رمز و SECRET_KEY تصادفی و محلی؛ نه در ZIP و نه در Git. `.local_state/` شامل SQLite، کلید و داده‌های آزمایشی است و نادیده گرفته می‌شود. این پوشه را نفرستید.
- نشست و فرم‌های CSRF استاندارد، مالک‌محور بودن queryها، escape متن، محدودیت طول/نوع و قیمت غیرمنفی اعمال می‌شود. این‌ها مرز Preview هستند، نه گواهی امنیت Production.
- `DEBUG=False`؛ فقط Host محلی و درخواست loopback. فایل‌های CSS/JS از خود برنامه‌اند؛ CDN، فونت یا سرویس خارجی نداریم. CSP اتصال بیرونی مرورگر را منع می‌کند؛ audit hook برنامه connect/sendto و DNS بیرونی را رد می‌کند. این hook یک sandbox سیستم‌عامل برای کد مخرب یا کتابخانه native نیست.
- سرور توسعه Django برای Production مناسب نیست؛ نه TLS، نه rate limit ورود عمومی، نه ادعای امنیت اینترنتی. فقط حساب/داده ساختگی روی دستگاه خودتان.
- متن خام گفتگو در این Preview تا پاک‌کردن دستی محیط محلی باقی می‌ماند؛ **retention و پاکسازی ۳۰روزه اجرا نشده**. داده واقعی مشتری وارد نکنید.
- برای رمز تازه (بدون پاک‌شدن داده): همان Python محیط را با `manage.py setup_demo --reset-password` اجرا کنید. اگر `--seed` بدهید، فقط وقتی هنوز فروشگاهی ندارید دو مورد ساختگی و یک دستیار نمونه ساخته می‌شود.
- برای شروع کاملاً تازه: سرور را متوقف، فقط پوشه `.local_state` همین Preview آزمایشی را با آگاهی از حذف همه داده‌های ساختگی‌اش پاک کنید، سپس migrate و setup_demo را دوباره اجرا کنید. هیچ دستور حذف خودکاری اجرا نمی‌شود.

## ۵. اجرای بررسی‌ها

از Python محیط خودتان استفاده کنید؛ در Windows مسیر `.venv\Scripts\python.exe` را جایگزین کنید:

```bash
.venv/bin/python manage.py check
.venv/bin/python manage.py migrate
.venv/bin/python manage.py test --verbosity 2
```

تست‌ها دو مالک ساختگی، CSRF واقعاً فعال، CRUD، ورودی نامعتبر/escape، constraint یک دستیار، پاسخ‌های داده‌محور، ممنوعیت bind عمومی و رد connect/DNS بیرونی را بررسی می‌کنند. گزارش واقعی اجرای تحویل در `evidence/` و `HANDOFF.md` است؛ نتایج اجرا‌نشده PASS نامیده نمی‌شوند. CI در این مأموریت ساخته/dispatch نشده است.

برای ساخت ZIP فقط از سورس و راستی‌آزمایی راه‌اندازی سرد:

```bash
python3.12 tools/package_preview.py /path/to/cac-preview-v0-pv0-01.zip
python3.12 tools/verify_zip.py /path/to/cac-preview-v0-pv0-01.zip /path/to/new-empty-directory
```

مسیر مقصد را تازه انتخاب کنید؛ اسکریپت پوشه موجود را بازنویسی نمی‌کند. verification محیط جدید می‌سازد، وابستگی نصب می‌کند، migrate/check/tests، ورود و جریان واقعی HTTP روی loopback و توقف/اجرای مجدد را انجام می‌دهد. رمز/کوکی/کلید چاپ نمی‌شوند. این تست HTTP **جای تست دستی مرورگر یا قضاوت مالک محصول را نمی‌گیرد**.

کد مستقل new-origin در `preview_v0/` از main `f9f465c3387833d44e537c163c9dacff75e352ac`؛ هیچ merge/cherry-pick از PR آزمایشی ندارد. SOURCE-001/GATE-SOURCE **BLOCKED**، Gate #9 **OPEN**، S0-09D **FAIL_SECURITY**، Lane3 **BLOCKED** و گیت‌های Production همگی حفظ شده‌اند. این ZIP سورس تاریخی بازیابی‌شده یا baseline پذیرفته‌شده نیست.
